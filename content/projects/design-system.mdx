## Overview

As Investigator Copilot expanded into multiple AI-powered workflows, the team needed a consistent interface that could scale across new features while reducing repetitive design work.

To address this, I created a reusable UI kit that established shared design foundations, standardized commonly used components, and provided documentation for designers and developers to build new experiences more consistently.

Although this project is referred to as a design system throughout the case study, it is more accurately described as a product-specific UI kit. It serves as the design foundation for Investigator Copilot and has not yet evolved into an organization-wide design system with governance and cross-product adoption.

## Problem

### No shared components or token system

There was no existing design system or UI library in place for the team. Without one, decisions on UI components and patterns had to be made repeatedly, and developers implemented components differently across the product — creating visual and behavioural inconsistency between different Investigator Copilot use cases.

## Process

### Auditing Existing Interfaces

I began by reviewing existing Investigator Copilot screens to identify recurring UI patterns and duplicated components. I identified frequently used interface elements, opportunities to standardise spacing, typography and colours, as well as components that could be reused across current and future features. As a team, we ran through the component list together and settled on a list that would form the basis of the UI kit.

### Establishing Design Foundations

Based on the developers' preference, I took shadcn/ui as the base set, adjusting styling and colour further from there to fit SPF branding. A set of primitive values formed the foundations of our design system, including:

- Colour tokens
- Typography
- Spacing
- Corner radius
- Shadows
- Grid and layout principles

### Naming design tokens

To balance implementation speed with project timelines, the colour system was intentionally simplified to two token tiers instead of the more common three-tier token architecture. With a small, stable component set, component-level tokens would have added additional unnecessary overhead.

This trade-off was discussed and agreed upon with developers, prioritizing faster adoption while still providing sufficient flexibility for the product's current needs.

### Supporting Adoption

Beyond creating the library itself, I migrated the existing ULTRA interface to use the new UI kit, to demonstrate how it can be applied across use cases.

## Outcome

The UI kit is now used across 4 Investigator Copilot use cases, and 1 upcoming feature currently in development.

It supports collaboration between 2 designers and 5 developers.

<Screenshot
  src="/projects/design-system/4-use-cases.png"
  alt="Four Investigator Copilot interfaces built with the shared UI kit: Live Transcription, Project ULTRA's report preview, File Transcript upload, and the Briefing Note Generator"
  caption="The UI kit applied across the 4 Investigator Copilot use cases it currently supports"

Although still early in its lifecycle, the UI kit has established a shared visual language for Investigator Copilot. It has helped standardise designs across Investigator Copilot use cases, reduce repeated component creation, improve consistency across designers and developers, and help the team move discussions to more productive issues.
