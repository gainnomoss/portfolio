## Overview

There was a gap in our workflow as a team: no existing design system or UI library was in place. The team had to spend time making decisions on UI components or patterns frequently, and developers also implemented components differently. I worked on a set of reusable components that improved consistency across the different use cases in Investigator Copilot.

## Problem

### No shared components or token system

There was no existing design system or UI library in place for the team. Without one, decisions on UI components and patterns had to be made repeatedly, and developers implemented components differently across the product — creating visual and behavioural inconsistency between different Investigator Copilot use cases.

## Process

### Choosing a base to build from

I worked together with developers to agree on a set of components we would deliver first. Based on the developers' preference, I took shadcn/ui as the base set, adjusting styling and colour further from there to fit SPF branding.

## Outcome

The component set has been adopted as the default set of components used across all Investigator Copilot use cases. As a team, this helped us make decisions more quickly, and freed us up to discuss issues beyond UI.
